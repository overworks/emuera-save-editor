# 🎮 Emuera Save Studio

[English](README.md) · **한국어** · [日本語](README.ja.md)

**✏️ 텍스트·바이너리 편집 · 🌐 한국어 / English / 日本語 · 🔒 파일은 브라우저 안에 보관**

브라우저에서 Emuera 세이브를 읽고 수정하는 앱입니다. `global.sav`를 포함한 텍스트·바이너리 세이브를 지원하며, 파일 업로드나 백엔드, 계정, 별도의 데이터베이스 서버가 필요하지 않습니다. 앱 화면은 영어·한국어·일본어를 지원합니다.

## 🚀 시작하기

브라우저에서 [Emuera Save Studio 열기](https://overworks.github.io/emuera-save-editor/?lang=ko)를 선택하세요. 설치 없이 사용할 수 있습니다. **샘플로 둘러보기**를 선택하면 자신의 파일을 열기 전에 가상 세이브로 사용해 볼 수 있습니다.

로컬에서 실행하려면 Node.js 22.x(22.12 이상), 24.x 또는 26.x와 npm을 설치한 뒤 프로젝트 디렉터리에서 다음 명령을 실행합니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 주소를 브라우저에서 엽니다.

최신 데스크톱 브라우저를 사용하세요. 현재 브라우저 테스트는 Chromium에서 데스크톱과 모바일 화면 크기를 대상으로 수행합니다.

앱은 헤더에서 전환하는 세 화면으로 구성됩니다. **시작**(세이브 또는 샘플 열기), **작업**(세이브를 연 뒤), **문서**(사용법, 작업 복구, 오프라인, 제한 사항)입니다. 문서를 열어도 열린 세이브와 수정 내용은 유지되며, `#guide`로 바로 연결할 수 있습니다.

## 🌐 언어 선택

상단 언어 선택기에서 **English**, **한국어**, **日本語**로 전환할 수 있습니다. 처음에는 브라우저가 선호하는 지원 언어를 사용하고, 지원하는 언어가 없으면 영어를 표시합니다. URL의 언어 지정(`?lang=en`, `?lang=ko`, `?lang=ja`)이 우선합니다. 언어를 선택하면 URL에 반영되어 쿠키나 localStorage를 사용하지 않아도 새로고침 후 유지되며 북마크로 보관할 수 있습니다.

언어를 바꿔도 열린 세이브, 수정 내용, 검색 조건, CSV 이름표는 유지됩니다. 버튼, 도움말, 오류, 알림은 번역하고 파일명, 변수명, 캐릭터명, CSV 이름표, 저장 값은 원문 그대로 표시합니다. 번역은 앱에 포함되어 있어 앱을 불러온 뒤에는 오프라인에서도 전환할 수 있습니다.

## ✏️ 세이브 편집하기

1. 파일 선택 버튼으로 `save*.sav` 또는 `global.sav` 파일 하나를 열거나 세이브 전용 드롭 영역에 끌어 놓습니다. 세이브를 연 뒤에는 파일명이 표시된 막대에 다른 세이브를 놓아 교체할 수 있습니다.
2. 공통·글로벌 변수 또는 캐릭터를 선택합니다. 변수명, CSV 이름표, 정확한 배열 인덱스로 검색할 수 있습니다. 다차원 인덱스는 `1:2:3`으로 입력합니다.
3. 값을 클릭하고 새 값을 입력한 뒤 변경을 적용합니다. **변경 내역** 탭에서 원본과 현재 값을 비교하고 개별 변경 또는 전체 변경을 되돌릴 수 있습니다.
4. **세이브 다운로드**를 선택하여 `original-name.edited.sav`를 저장합니다.
5. 원본의 백업을 보관한 뒤 수정본을 원래 파일명으로 바꿔 게임의 세이브 폴더에 넣습니다.

앱은 별도 파일을 다운로드하며 원본을 덮어쓰지 않습니다. 다운로드한 파일은 원래 형식과 인코딩을 유지합니다. 변경하지 않았다면 원본과 바이트 단위로 동일합니다. 수정본은 다운로드 전에 검증하지만, 게임의 규칙이나 각 값의 의미까지 확인하지는 않습니다.

## 📐 바이너리 배열 크기 변경

바이너리 세이브를 열고 **변수 그룹**에서 배열을 선택한 뒤 **배열 크기 변경**을 누릅니다. 각 차원의 길이를 입력하고 변경을 적용하세요. 1–3차원 정수·문자열 배열을 차원 수를 유지하면서 확장하거나 축소할 수 있고, 요소가 0개인 크기도 가능합니다. 전체 요소는 1억 개 이하여야 합니다.

기존 값은 좌표를 유지하며, 새 칸에는 `0` 또는 빈 문자열이 들어갑니다. 새 범위를 벗어난 칸은 다운로드에서 제외되며, 같은 세션에서 크기를 다시 늘리면 해당 값과 수정 내용이 복구됩니다. **변경 내역**에서 값 수정과 크기 변경을 함께 확인하고 개별 되돌리기나 **전체 되돌리기**를 사용할 수 있습니다. 원본 크기로 되돌리면 추가한 칸의 수정은 출력에서 제외되며, 적용 중인 변경이 없으면 원본과 바이트 단위로 동일하게 출력합니다.

세이브에 저장된 크기만 변경합니다. 게임에서는 별도로 선언한 배열 크기를 사용하므로 추가한 칸을 무시할 수 있습니다. 텍스트 세이브에는 전체 배열 크기가 기록되지 않아 텍스트 배열의 크기는 변경할 수 없습니다.

## 🧩 바이너리 변수 추가와 삭제

바이너리 세이브를 열고 **변수 추가**를 누릅니다. 이름, 범위, 정수·문자열 자료형, 단일 값 또는 배열 차원을 입력하세요. 공통·글로벌 변수는 단일 값과 1–3차원을 지원합니다. 캐릭터에서는 기본 변수(단일 값 또는 1–2차원)와 스크립트에서 선언한 `#DIM`·`#DIMS` 변수(1–2차원)를 선택합니다. 새 값은 `0` 또는 빈 문자열로 시작하며, 길이가 0인 배열도 가능하고 동일하게 1억 요소 제한을 적용합니다.

이름은 문자나 밑줄로 시작하고 문자·결합 문자·숫자·밑줄만 포함해야 하며, UTF-16 코드 단위 128개 이하여야 합니다. 같은 범위에서 사용 중인 이름은 대소문자 구분 없이 중복할 수 없습니다. 이는 편집기의 입력 제한이며 게임의 변수 선언을 검증하는 것은 아닙니다.

삭제하려면 **변수 그룹**에서 변수를 선택하고 **변수 삭제**를 누르세요. **변경 내역**에서 추가·삭제를 확인하고 개별적으로 되돌릴 수 있습니다. 원본 변수를 삭제하면 값 수정과 크기 변경을 복원할 때까지 숨깁니다. 새로 추가한 변수를 삭제하면 추가와 관련 수정 내용을 취소합니다. 삭제한 이름으로 새 변수를 추가했다면 먼저 새 변수 추가를 취소해야 원본을 복원할 수 있습니다. 한 범위의 모든 변수를 삭제해도 **전체 되돌리기**로 원본 바이트를 복원합니다.

이 기능은 세이브의 기록만 바꾸며 게임의 변수 선언을 추가하거나 삭제하지 않습니다. 이름·자료형·범위·차원이 게임의 선언과 맞아야 하며, 없거나 알 수 없는 기록은 무시되거나 게임의 기본값을 사용할 수 있습니다. [바이너리 변수 동작과 소스 근거(영어)](docs/binary-variables.md)를 참고하세요.

## 📝 텍스트 확장 변수 추가와 삭제

확장 구분자가 있는 텍스트 세이브에서 **변수 추가**를 누르거나, **변수 그룹**에서 이름이 기록된 확장 변수를 선택하고 **변수 삭제**를 누르세요. 게임의 선언에 맞는 기본·사용자 정의 구역을 선택합니다. 현재 세이브 버전에서 허용하는 자료형과 차원만 표시합니다. `MONEY`, `NAME`, `GLOBAL`처럼 고정 순서인 기본 구역 변수는 개별 추가·삭제할 수 없습니다. 확장 구분자가 없는 레거시 세이브에는 변수를 추가할 수 없습니다.

| 텍스트 확장 구역 | 정수 | 문자열 |
| --- | --- | --- |
| 캐릭터 기본 변수 | 단일 값·1차원, 1803부터 2차원 | 단일 값·1차원 |
| 공통 기본 변수 | 단일 값·1차원, 1708부터 2차원, 1729부터 3차원 | 단일 값·1차원 |
| 1808부터 공통·글로벌 사용자 정의 변수 | 1–3차원 | 1차원 |

새 배열은 지정한 칸을 모두 `0` 또는 빈 문자열로 실제 기록합니다. 세이브 전체에서 저장된 값 100만 개, 텍스트 100만 줄, 64 MiB 제한을 지켜야 합니다. 빈 다차원 배열은 모든 길이를 0으로 지정하세요. 기존 텍스트 배열의 저장된 칸과 행별 길이는 유지하며, 배열 크기 변경과 텍스트 형식의 사용자 정의 캐릭터 변수 추가는 지원하지 않습니다. 변수 이름은 바이너리와 같은 입력 규칙을 따르고 원본 인코딩으로 표현할 수 있어야 하며, 예약된 구분자는 사용할 수 없습니다.

**변경 내역**, 개별 되돌리기, **전체 되돌리기**, 캐릭터 복제, 선택적 로컬 복구에 함께 반영됩니다. 원본 변수를 삭제하면 숨겨진 수정 내용을 유지하고, 새 변수의 추가를 취소하면 해당 수정 내용도 삭제합니다. 수정하지 않은 기록·구분자·BOM·인코딩·기존 줄바꿈을 보존하며 새 기록은 해당 구역의 줄바꿈을 사용합니다. 모든 변경을 되돌리면 원본 바이트를 정확히 복원합니다. 세이브에 기록을 추가해도 게임 변수를 선언하거나 초기화하지는 않습니다. [텍스트 변수 동작과 소스 근거(영어)](docs/text-variables.md)를 참고하세요.

## 👥 캐릭터 복제와 삭제

일반 텍스트·바이너리 세이브에서 캐릭터를 선택하고 **캐릭터 복제**를 누르세요. 수정 사항을 포함한 현재 값·배열 크기·변수 구성을 독립적으로 복제해 목록 끝에 추가합니다. `NAME`과 `NO`도 복사하므로 필요하면 복제 후 수정하세요. `NO`는 화면의 저장 순서(`#0`, `#1`, …)와 별개이며 중복될 수 있습니다. 빈 캐릭터도 복제할 수 있지만, 복제할 기존 캐릭터가 없으면 새 캐릭터를 만들 수 없습니다. 게임 스크립트나 CSV로 캐릭터를 초기화하지는 않습니다.

**캐릭터 삭제** 확인창에서 영향을 받는 표준 참조를 확인할 수 있습니다. 뒤의 캐릭터는 한 칸씩 앞으로 이동합니다. 정수 칸 `TARGET:0`·`ASSI:0`·`MASTER:0`·`PLAYER:0`이 같은 캐릭터를 가리키도록 조정하고, 삭제 대상 참조는 `-1`로 바꿉니다. 음수와 이미 범위를 벗어난 값은 유지합니다. 게임별 별도 참조, 나머지 배열 칸, `NO`, `RELATION` 인덱스는 조정하지 않으므로 게임이 다른 곳에 저장한 참조는 직접 확인하세요.

**변경 내역**에 캐릭터 작업과 자동 참조 조정도 표시합니다. 원본 캐릭터의 삭제를 되돌리면 값·변수 편집 내용·원래 순서를 복구하며, 직접 수정하지 않은 참조도 복원합니다. 표준 참조를 직접 수정하면 입력 당시 그 순서에 있던 캐릭터를 계속 가리킵니다. 자동 조정을 덮어쓰려면 참조 값을 편집하고, 조정 자체를 되돌리려면 캐릭터 작업을 되돌리세요. 복제본을 삭제하면 해당 복제와 편집 내용을 취소합니다. 모든 캐릭터를 삭제한 뒤에도 **전체 되돌리기**로 원본 바이트를 복원합니다. 글로벌 세이브에서는 이 기능을 제공하지 않습니다.

텍스트에서는 고정 순서의 기본 구역과 캐릭터 확장 구역을 함께 복제하거나 삭제합니다. 원본 인코딩·BOM·구분자·줄바꿈을 보존하며, 새 경계에서 단독 CR과 LF가 합쳐지는 경우에만 LF 하나를 삽입해 두 줄을 유지합니다. 저장된 참조 셀만 조정하고 생략된 셀은 만들지 않습니다. 복제한 텍스트 배열도 행별 길이와 편집 가능한 셀을 유지합니다.

소스 근거, 참조 규칙과 검증 범위는 [바이너리 캐릭터 동작(영어)](docs/binary-characters.md)과 [텍스트 캐릭터 동작(영어)](docs/text-characters.md)을 참고하세요.

## 🎮 게임 프리셋

편집기의 **게임 프리셋**을 선택하면 번역된 항목 이름·설명과 자주 쓰는 항목 바로가기를 볼 수 있습니다. 목록은 **eraTWKR Textbung(TWKR 1.20 기반)**, **eratohoK 1.29.3**, **eraMegaten KR Rev.143**, **ShinEraTenseiP 0.5.9**를 포함합니다. 각 프리셋에 자료 기준 판본과 변수 정의 링크를 표시합니다. 게임 코드와 버전으로 후보를 안내하며, 같은 코드를 쓰는 게임들을 버전으로 구분할 수 없으면 직접 선택합니다. 코드·버전 차이를 표시하지만, 식별 정보가 일치해도 모든 패치나 엔진 개조판의 호환성을 보장하지는 않습니다.

**자주 쓰는 항목**을 펼치고 캐릭터를 선택하면 해당 캐릭터의 바로가기가 활성화됩니다. 공통 소지금이 포함된 프리셋에서는 바로 열 수 있습니다. 바로가기는 저장된 항목을 열며, 현재 화면 언어의 프리셋 이름·설명으로도 선택한 영역과 변수 그룹 안에서 검색할 수 있습니다. 없거나 형식이 다른 항목은 사용할 수 없습니다. CSV 이름을 우선 표시하고 프리셋 안내는 별도로 덧붙입니다.

프리셋을 선택하거나 바꿔도 세이브 값과 편집 내용은 유지됩니다. 언어 전환이나 파일 열기 실패 시 선택을 유지하고 다른 세이브를 성공적으로 열면 초기화합니다. 로컬 작업 복구를 켜면 선택한 프리셋도 복원합니다. 앱을 읽은 뒤에는 오프라인에서도 사용할 수 있습니다. 일부 항목의 안내를 제공하는 기능이며 전체 게임 데이터나 값 자동 변경 기능은 아닙니다. [프리셋 대응표·자료 판본·검증 범위(영어)](docs/game-presets.md)를 참고하세요.

## 🏷️ CSV 이름표와 인코딩

세이브를 연 뒤 **게임 CSV 이름표** 영역에 게임의 `ABL.csv`, `TALENT.csv`, `EXP.csv`, `PALAM.csv`, `ITEM.csv`, `FLAG.csv`, `CFLAG.csv` 등 지원하는 표준 이름표 파일을 끌어 놓습니다. 여러 CSV를 한 번에 놓거나 **CSV 불러오기** 버튼으로 함께 선택할 수 있습니다. 점선으로 표시된 세이브 영역과 CSV 영역은 각각 해당 파일을 받으며, 다른 곳에 놓으면 파일을 열지 않습니다. 이름표는 값을 이름으로 찾도록 돕는 선택 기능이며 세이브 내용이나 배열 크기를 바꾸지 않습니다. 이름표가 충돌하면 먼저 읽은 이름을 유지하고 알림을 표시합니다.

`Chara*.csv`를 불러오면 참고용 이름·호칭·별명·주인 호칭을 표시합니다. 파일의 `NO` 또는 `番号`를 세이브의 현재 `NO`와 연결하며, 파일명이나 캐릭터 순서로 연결하지 않습니다. 캐릭터를 선택하고 **캐릭터 CSV**를 펼치면 정보를 볼 수 있습니다. 세이브의 이름 항목과 `NO` 옆에도 이름표가 표시되며, `RELATION` 인덱스에는 해당 캐릭터 번호의 이름이 붙습니다. 이름표로 검색할 수 있고, `RELATION`은 호칭과 별명으로도 찾을 수 있습니다. `NO`를 수정하면 연결 대상도 바뀝니다. 세이브의 이름은 그대로이며 초기 능력치나 캐릭터 추가는 적용하지 않습니다. 캐릭터 번호가 중복되면 첫 번째 파일의 정보를 유지합니다.

`_Rename.csv`는 엔진의 `치환할 내용,별칭` 형식으로 검색 치환을 제공합니다. 예를 들어 `ABL:0,focus`를 불러오면 `[[focus]]`로, `0,skill`을 불러오면 `ABL:[[skill]]`로 검색할 수 있습니다. 치환한 검색어는 검색창 아래에 표시됩니다. 선택한 범위 안에서 변수명·이름표·숫자 인덱스 또는 `TA:3:2:1` 같은 참조를 찾습니다. 별칭은 대소문자를 구분하고, 불러온 규칙 순서대로 한 번씩 치환하며, 중복 정의는 첫 번째 내용을 유지합니다. 치환은 검색 입력에만 적용합니다. CSV 이름이나 세이브 값을 바꾸지 않으며, 식이나 `TARGET` 같은 동적 캐릭터 지정은 계산하지 않습니다.

CSV는 한 세션에서 합계 64 MiB까지 불러올 수 있습니다. 다른 세이브를 성공적으로 열면 초기화하며, 로컬 작업 복구를 켜면 작업과 함께 CSV 정보도 복원합니다. 지원 항목, 쉼표 이스케이프, 제한은 [CSV 구문과 소스 근거(영어)](docs/csv-metadata.md)를 참고하세요.

텍스트 인코딩은 UTF-8을 먼저 검사하고, 유효하지 않으면 CP932/Shift-JIS를 사용합니다. 일부 바이트열은 두 인코딩에서 모두 유효합니다. 글자가 잘못 표시되면 **읽기 인코딩**을 올바르게 선택하고 **선택한 인코딩으로 다시 읽기**를 누르세요. 다시 읽을 때는 확인을 거쳐 변경 사항을 버립니다. 선택한 인코딩은 이후에 불러오는 CSV에도 적용됩니다.

범위를 벗어난 정수, 원본 텍스트 인코딩으로 표현할 수 없는 문자, 예약된 텍스트 구분자, 텍스트 값의 줄바꿈, 손상되거나 지원하지 않는 파일은 오류로 처리합니다. 자동 호환성 검증에는 원본 엔진의 저장 코드로 생성하고 읽은 가상 세이브를 사용합니다. 사용자가 실제 세이브 데이터의 불러오기·수정·출력도 확인했습니다. 이 확인은 게임에서의 재로드나 모든 게임·포크의 호환성, 배열 크기 변경·변수 추가·삭제·캐릭터 복제·삭제의 실제 세이브 검증까지 의미하지는 않습니다.

## 🗺️ 향후 지원 계획

미지원 기능을 순차적으로 구현하고 있습니다. 바이너리 배열 크기 변경, 바이너리·텍스트 확장 변수 추가·삭제, 일반 텍스트·바이너리 캐릭터 복제·삭제, 캐릭터 CSV 이름 정보, `_Rename.csv` 검색 치환, 선택적 로컬 작업 복구, 오프라인 재접속·PWA 설치는 구현했으며, 남은 항목은 다음과 같습니다.

- 복제 없이 새 캐릭터 생성.
- 필요한 크기 정보를 명시적으로 제공하는 텍스트 배열 크기 변경과 형식 변환.

- 별도의 실행 설계가 필요한 ERB/ERH 실행.

각 항목은 구현과 검증을 마치기 전까지 미지원 상태이며, 제공 일정은 정해지지 않았습니다.

## 💾 로컬 작업 복구

**이 브라우저에 작업 저장**은 기본으로 꺼져 있습니다. 켜면 한 작업을 브라우저에 자동 저장하고 새로고침하거나 같은 사이트에 다시 방문할 때 복원합니다. 원본 파일, 적용한 값·구조 수정, 되돌리기 상태, 불러온 CSV, 읽기 인코딩, 게임 프리셋, 검색어, 선택한 영역·변수와 페이지를 보관합니다. 열린 편집창에서 아직 적용하지 않은 입력은 저장하지 않습니다. 다른 세이브를 성공적으로 열면 보관본을 교체하며, 열기에 실패하면 기존 작업을 유지합니다.

페이지를 떠나기 전에 **브라우저에 저장됨**을 확인하세요. 복구 기능을 끄면 확인 후 보관된 작업을 삭제하며 현재 열린 작업은 메모리에 유지합니다. 저장 오류가 나도 열린 수정 내용과 마지막으로 저장된 보관본을 유지합니다. **다시 저장**을 누르거나 수정본을 다운로드하세요. 다른 탭에서 보관본을 변경하거나 삭제하면 이전 상태의 탭은 자동 저장을 중지합니다.

현재 브라우저 프로필과 사이트 경로별 IndexedDB를 사용하며 브라우저·기기 간 동기화는 하지 않습니다. 복구 기록은 작업 10만 회, 원본 파일·CSV를 포함해 128 MiB까지 보관합니다. 한도를 넘으면 수정본을 다운로드하고 다시 열어 새 작업을 시작하세요. 브라우저 데이터 삭제, 저장 공간 정리, 비공개 창 종료로 보관본이 사라질 수 있으므로 다운로드한 백업도 유지하세요. 오프라인 앱 준비와 작업 복구는 별개이며, 오프라인에서 다시 열 때 작업도 복원하려면 복구를 켜야 합니다.

## 📴 오프라인 사용과 설치

연결된 상태에서 배포용 앱에 접속하고 시작·작업 화면 하단의 복구 설정 옆에 **오프라인 재접속 준비됨**이 표시될 때까지 기다리세요. 이후에는 이 브라우저에서 연결 없이 앱을 다시 열고 샘플과 세 언어를 모두 사용할 수 있습니다. 첫 방문에는 연결이 필요합니다. 오프라인 재접속에는 HTTPS 또는 localhost와 서비스 워커·앱 저장소를 허용하는 브라우저가 필요하며, 개발 서버에서는 오프라인 사용을 준비하지 않습니다. 브라우저 데이터 삭제나 저장 공간 정리로 앱 캐시가 사라질 수 있습니다. **오프라인 사용·설치**를 펼쳐 준비를 다시 시도하거나 업데이트를 확인할 수 있습니다.

다시 열 때 수정 작업도 이어가려면 **이 브라우저에 작업 저장**을 켜고 **브라우저에 저장됨**을 확인하세요. 끈 상태에서는 닫기 전에 수정본을 다운로드하세요. 앱을 설치해도 복구는 자동으로 켜지지 않으며, 복구를 끄면 보관된 작업은 삭제하지만 앱 캐시는 유지합니다.

지원하는 환경에서는 **앱 설치** 또는 브라우저의 설치 메뉴를 사용하세요. iPhone·iPad에서는 **공유 → 홈 화면에 추가**를 사용합니다. 설치는 선택 사항이며 지원 여부는 브라우저에 따라 다릅니다. 일반 브라우저 탭에서도 계속 사용할 수 있습니다. 설치한 앱을 실행하면 브라우저가 선호하는 지원 언어를 사용하며, 언어별 북마크는 URL의 `lang` 값을 유지합니다.

**새 버전이 준비되었습니다**가 표시되면 편집창의 미적용 입력을 먼저 적용하고, 각 창의 작업을 저장하거나 다운로드하세요. 이 앱의 모든 탭과 설치한 앱 창을 닫은 뒤 다시 열면 새 버전이 적용됩니다. 업데이트 때문에 편집창을 자동으로 새로고침하지 않으며, 다른 앱 창이 열려 있으면 탭 하나만 새로고침해도 이전 버전을 계속 사용할 수 있습니다. 업데이트 준비에 실패하면 기존 오프라인 버전을 유지합니다. `file://` 직접 실행은 계속 미지원입니다.

## 🔒 개인정보와 작업 내용

세이브와 CSV 내용은 기본적으로 브라우저 메모리에 보관하며, 로컬 작업 복구를 켜면 이 브라우저의 IndexedDB에도 저장합니다. 오프라인 준비는 가상 샘플을 포함한 배포용 앱 파일만 브라우저의 Cache Storage에 자동으로 보관하며, 불러온 세이브와 CSV는 이 캐시에 넣지 않습니다. 업로드 API, 분석 도구, 외부 폰트, CDN 의존성이 없습니다. 쿠키와 localStorage를 사용하지 않으며 언어 설정은 URL에만 보관합니다.

앱을 불러온 뒤에는 네트워크 연결 없이 편집, CSV 불러오기, 다운로드와 활성화한 로컬 저장이 가능합니다. 앱 준비가 끝나면 오프라인 재접속도 가능합니다. 앱을 설치했더라도 로컬 작업 복구를 끄면 새로고침하거나 페이지를 닫을 때 작업이 사라집니다.
