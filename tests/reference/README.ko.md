## 검증 범위

각 자료에 가상 표준 이름표, `Chara*.csv` 이름 정보, `_Rename.csv` 검색 치환을 먼저 불러옵니다. 편집하지 않은 출력은 원본과 바이트 단위로 같아야 합니다. 아래의 값 편집 비교 중에도 CSV 정보를 유지합니다. CSV 해석 규칙은 엔진의 CSV 로더를 실행하는 대신 소스에 근거한 단위 테스트로 확인합니다. [CSV 소스 근거(영어)](../../docs/csv-metadata.md)를 참고하세요.

원본 작성기는 일반·글로벌 세이브를 바이너리, UTF-8 텍스트, CP932 텍스트로 저장하여 총 6개 자료를 생성합니다. 캐릭터와 값은 가상으로 작성했으며 게임의 세이브에서 가져오지 않았습니다. 자료 생성 시 일반 바이너리 세이브를 [src/assets/demo.sav](../../src/assets/demo.sav)로 복사합니다.

TypeScript 편집기가 세이브를 수정한 뒤 원본 판독기로 결과를 읽습니다. [scripts/reference-check.ts](../../scripts/reference-check.ts)는 편집 전후의 전체 값 사전을 비교하여 의도한 값만 변경되었는지 확인합니다. 텍스트 판독기는 호스트에서 배열 크기를 제공받아야 합니다. 어댑터는 기본 구역에 128요소 배열을 사용하며, 이는 테스트 자료에 충분한 크기일 뿐 다른 게임의 배열 크기를 나타내지 않습니다.

바이너리 세이브에서는 빈 배열을 포함해 저장된 각 배열의 차원별 길이도 출력합니다. 일반·글로벌 자료에서 제공하는 각 자료형과 차원 수에 대해 확장, 축소, 축별 확장·축소 혼합, 비우기를 검사합니다. 예상 값은 원본 판독기가 수정 전에 읽은 사전의 동일 좌표 값과 명시적으로 입력한 새 값으로 구성합니다. 모든 값과 크기를 되돌리면 원본 바이트가 복원되어야 합니다.

크기 변경의 형식 근거는 upstream의 `EraBinaryDataReader1808.ReadIntArray*`와 `ReadStrArray*` 메서드가 `ReadInt32()`로 읽는 차원별 길이입니다. 판독기는 게임이 제공하는 대상 배열의 크기를 별도로 사용하며 겹치는 영역만 복사할 수 있습니다. 따라서 세이브의 배열 크기를 바꿔도 게임의 변수 선언은 바뀌지 않습니다. 어댑터에서는 출력한 모든 칸을 검증하기 위해 세이브에 기록된 크기로 대상 배열을 만듭니다.

변수 추가·삭제 검증에서는 바이너리 판독기가 기록의 이름·범위·자료형 태그·순서·구분자·캐릭터 끝도 출력합니다. 두 바이너리 자료와 함께 원본 작성기로 임시 생성한 빈 캐릭터 및 사용자 정의 구역이 없는 캐릭터 자료를 비교합니다. 공통·글로벌 단일 값과 모든 자료형·차원 수의 배열, 빈 배열, 캐릭터 기본·사용자 정의 변수를 추가하고 원본 변수 하나를 삭제한 뒤, 별도로 원본 변수를 모두 삭제합니다. 전체 값·차원별 길이·배치가 명시적으로 구성한 예상 결과와 같아야 하며, 전체 되돌리기로 원본 바이트를 복원해야 합니다. 임시 자료는 `.reference/edited`에 생성하며 저장소의 자료를 덮어쓰지 않습니다. 구역과 차원 수 제한은 [바이너리 변수 소스 근거(영어)](../../docs/binary-variables.md)를 참고하세요.

게임 실행 없이 저장 코드의 호환성을 검증합니다. 게임 스크립트 규칙, 실제 사용자 세이브, 모든 Emuera 포크를 검증하지는 않습니다. C# 코드는 개발 검증에만 사용하며 브라우저 번들에는 포함하지 않습니다.

캐릭터 작업은 원본 작성기로 별도의 임시 자료를 생성해 검증합니다. 빈 구역과 구분자가 없는 구역을 포함한 캐릭터 3명, TARGET·ASSI·MASTER·PLAYER, 알 수 없는 게임별 참조, 64비트 극값을 담습니다. 수정한 캐릭터 복제와 삭제, 전체 캐릭터 삭제, 빈 구역·구분자 없는 구역의 복제, 직접 수정한 참조의 복원, 복제본 참조, 참조 중인 복제본 취소의 6가지 시나리오를 비교합니다. 원본 판독기의 사전에 명시적 값 수정과 범위 재배치를 적용해 예상 결과를 구성하고, 전체 값·차원별 길이·캐릭터 수·배치를 비교합니다. 전체 되돌리기와 개별 캐릭터 복원으로 원본 바이트가 복구되어야 합니다. 편집기의 참조 처리 규칙과 한계는 [캐릭터 소스 근거(영어)](../../docs/binary-characters.md)를 참고하세요.

## 실행 방법

프로젝트의 npm 의존성과 .NET 8 SDK를 설치한 뒤 저장소 루트에서 실행합니다.

```sh
npm run test:reference
```

실행 파일이 `PATH`에 없다면 `DOTNET=/absolute/path/to/dotnet`을 설정합니다. [scripts/oracle.ts](../../scripts/oracle.ts)는 어댑터를 `.reference/bin`에 빌드하며 수정된 파일은 `.reference/edited`에 저장됩니다. 둘 다 버전 관리에서 제외되는 빌드·테스트 결과입니다.

저장소의 세이브 자료 6개와 내장 샘플을 의도적으로 재생성하려면 실행합니다.

```sh
npm run fixtures
```

재생성 후 자료의 변경 내용을 검토하고 호환성 검증을 다시 실행하세요. 테스트 자료가 저장소에 포함되어 있으므로 일반 코어 테스트에는 .NET이 필요하지 않습니다.
