[English](README.md) · [한국어](README.ko.md) · **日本語**

## 検証範囲

各テストデータに、架空の標準ラベル、`Chara*.csv` の名前情報、`_Rename.csv` の検索用置換を最初に読み込みます。未編集の出力は元のファイルとバイト単位で同一でなければなりません。以下の値の編集比較中も CSV 情報を保持します。CSV の解析規則はエンジンの CSV ローダーを実行せず、ソースに基づく単体テストで確認します。[CSV のソースの根拠（英語）](../../docs/csv-metadata.md)を参照してください。

元の書き込みコードで、通常・グローバルセーブをバイナリ、UTF-8 テキスト、CP932 テキストとして保存し、計 6 個のテストデータを生成します。キャラクターと値は架空のもので、ゲームのセーブから取り出したものではありません。生成時には通常のバイナリセーブを [src/assets/demo.sav](../../src/assets/demo.sav) にもコピーします。

TypeScript の編集機能でセーブを変更し、その結果を元の読み込みコードで読み込みます。[scripts/reference-check.ts](../../scripts/reference-check.ts) は編集前後の値の辞書全体を比較し、意図した値だけが変わったことを確認します。テキストの読み込みコードには、ホストが配列サイズを渡す必要があります。アダプターは基本セクションに 128 要素の配列を使います。これはテストデータに十分なサイズであり、他のゲームの配列サイズを示すものではありません。

バイナリセーブでは、空配列を含めて保存された各配列の次元別の長さも出力します。通常・グローバルのテストデータにある各型と次元数について、拡張、縮小、軸ごとの拡張と縮小の組み合わせ、空配列への変更を検査します。期待値は、元の読み込みコードによる編集前の辞書の同じ座標の値と、明示的に設定した新しい値から作ります。値とサイズをすべて元に戻すと、元のバイト列が復元されなければなりません。

サイズ変更の形式上の根拠は、upstream の `EraBinaryDataReader1808.ReadIntArray*` と `ReadStrArray*` が `ReadInt32()` で読み込む次元別の長さです。読み込みコードはゲーム側が渡す対象配列のサイズを別途使い、重なる範囲だけをコピーする場合があります。そのためセーブの配列サイズを変更しても、ゲームの変数宣言は変わりません。アダプターは、出力した全要素を検証するために、セーブのサイズに合わせた対象配列を作ります。

変数の追加・削除の検証では、バイナリの読み込みコードがレコードの名前・範囲・型タグ・順序・区切り・キャラクター終端も出力します。2 個のバイナリデータに加え、元の書き込みコードで一時生成した、空のキャラクターとユーザー定義セクションのないキャラクターのデータを比較します。共通・グローバルの単一値とすべての型・次元数の配列、空配列、キャラクターの組み込み・ユーザー定義変数を追加し、元の変数を 1 個削除します。さらに別の比較で元の変数をすべて削除します。全値・次元別の長さ・配置が明示的に作った期待値と一致し、リセットで元のバイト列が復元される必要があります。一時データは `.reference/edited` に生成し、コミット済みのデータを上書きしません。セクションと次元数の制限は [バイナリ変数のソースの根拠（英語）](../../docs/binary-variables.md)を参照してください。

ゲームを実行せずに保存コードの互換性を確認します。ゲームスクリプトのルール、実際のユーザーのセーブ、すべての Emuera 派生版を検証するものではありません。C# コードは開発時の検証専用で、ブラウザーのバンドルには含まれません。

キャラクター操作では、元の書き込みコードで別の一時データを生成します。空のブロックと区切りのないブロックを含む 3 人のキャラクター、TARGET・ASSI・MASTER・PLAYER、不明なゲーム独自の参照、64 ビットの極値を含みます。編集済みキャラクターの複製と削除、全キャラクターの削除、空・区切りなしブロックの複製、手動参照の復元、コピーへの参照、参照中コピーの取り消しの 6 シナリオを比較します。元の読み込みコードの辞書に明示的な値の編集と範囲の再割り当てを適用して期待値を作り、全値・次元別の長さ・キャラクター数・配置を比較します。リセットと個別の復元で元のバイト列が戻る必要があります。編集機能の参照規則と制限は [キャラクターのソースの根拠（英語）](../../docs/binary-characters.md)を参照してください。

## 実行方法

プロジェクトの npm 依存関係と .NET 8 SDK をインストールし、リポジトリのルートから実行します。

```sh
npm run test:reference
```

実行ファイルが `PATH` にない場合は `DOTNET=/absolute/path/to/dotnet` を設定します。[scripts/oracle.ts](../../scripts/oracle.ts) はアダプターを `.reference/bin` にビルドし、編集結果は `.reference/edited` に保存されます。どちらもバージョン管理から除外されるビルド・テスト出力です。

コミット済みのセーブデータ 6 個と内蔵サンプルを意図的に再生成する場合は、次を実行します。

```sh
npm run fixtures
```

再生成後はデータの差分を確認し、互換性検証を再実行してください。テストデータはリポジトリに含まれているため、通常のコアテストには .NET は不要です。
