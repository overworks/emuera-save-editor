# Emuera Save Studio

Emuera 세이브를 브라우저 안에서 읽고 수정하는 한국어 웹앱입니다. 파일을 외부로 전송하지 않으며 백엔드, 계정, 데이터베이스가 필요하지 않습니다.

## 실행

Node.js 22.12+, 24.x 또는 26.x와 npm이 필요합니다. 개발 및 빌드를 위한 Node.js이며, 배포된 앱을 사용하는 사람에게는 브라우저만 필요합니다.

```sh
npm ci
npm run dev
```

개발 서버에 표시되는 주소를 브라우저에서 엽니다. 시작 화면의 **샘플로 둘러보기**는 엔진 저장 코드로 생성한 가상 세이브를 엽니다.

## 사용 방법

1. `save*.sav` 또는 `global.sav` 하나를 선택하거나 화면에 끌어 놓습니다.
2. 공통 변수 또는 캐릭터를 선택합니다. 변수명, CSV 이름표, 정확한 배열 인덱스로 검색할 수 있습니다. 다차원 인덱스는 `1:2:3`으로 입력합니다.
3. 현재 값을 클릭하고 새 값을 적용합니다. 변경 내역 탭에서 수정 전후를 비교하거나 개별/전체 되돌리기를 사용할 수 있습니다.
4. **세이브 다운로드**로 `원본이름.edited.sav`를 저장합니다. 게임에서 사용하려면 원본의 백업을 보관한 뒤 수정본을 원래 파일명으로 바꿔 세이브 폴더에 넣습니다.

게임의 `ABL.csv`, `TALENT.csv`, `EXP.csv`, `PALAM.csv`, `ITEM.csv`, `FLAG.csv`, `CFLAG.csv` 등을 **CSV 불러오기**로 선택하면 배열 인덱스에 이름이 붙습니다. CSV를 불러오지 않아도 편집할 수 있습니다. 이름표는 세이브 내용이나 배열 크기를 바꾸지 않습니다. 중복 항목은 먼저 읽은 이름을 유지하며 알림으로 표시합니다.

텍스트 인코딩은 UTF-8을 우선 검사하고, 올바르지 않으면 CP932/Shift-JIS로 읽습니다. 둘 다 유효한 바이트열은 자동 구분할 수 없으므로 표시된 글자가 다르면 인코딩을 직접 선택하여 다시 읽습니다. 읽기 인코딩 설정은 CSV에도 적용됩니다.

## 호환 범위와 보존 방식

기준은 표준 **Emuera 1.824** 원본 소스 보존 커밋 [`85db4cbd`](https://github.com/0x00000FF/Emuera/tree/85db4cbd5eb2efe6c5b5449ada351a21a20db60b)입니다.

| 항목 | 지원 |
| --- | --- |
| 파일 종류 | 일반 진행 세이브, 글로벌 세이브 |
| 텍스트 | 줄 단위 기본 구역, 확장 구역, UTF-8/BOM 및 CP932/Shift-JIS |
| 바이너리 | 형식 버전 1808, little-endian, UTF-16LE 문자열과 .NET 길이 접두사 |
| 값 | signed 64비트 정수, 문자열, 최대 3차원 배열 |
| 편집 | 기존 값과 선언된 바이너리 배열 범위 안의 생략된 0/빈 문자열 |
| CSV | 인덱스·이름 행, 대소문자 구분 없는 표준 파일명, 줄 주석과 이름 별칭 |

텍스트 세이브는 일반적인 CSV 파일과 달리 `__FINISHED`와 `__EMU_SEPARATOR__` 등의 엔진 문법을 사용합니다. 기본 구역의 변수 순서는 엔진과 같습니다. 1700/1708/1729/1803/1808 확장 구분자를 구분하며, 테스트 기준 엔진이 생성한 1808 형식을 중점 검증했습니다. 텍스트 다차원 문자열 배열은 기준 엔진 자체에서 지원하지 않습니다.

정수는 `bigint`로 보관하고 입력과 화면 표시에 10진 문자열을 사용합니다. 변경이 없으면 원본 바이트를 그대로 내보냅니다. 텍스트는 변경된 값의 바이트 구간만 교체하고, 바이너리는 변경된 변수만 다시 인코딩합니다. 다른 구역, 헤더, 변수 순서, BOM, 줄바꿈은 그대로 유지합니다. 다운로드 직전에 수정본을 재파싱하여 변수 구조와 모든 논리적 값을 확인합니다.

바이너리에서 생략된 배열 값은 메모리에 모두 펼치지 않습니다. 편집 표는 50개씩 조회합니다. 파일은 64 MiB, 배열 하나는 1억 요소, 파일 전체에 명시된 값은 100만 개, 텍스트는 100만 줄까지 지원합니다. 원본 인코딩으로 표현할 수 없는 문자, 텍스트 구분자/줄바꿈, 범위를 벗어난 정수, 잘린 파일, 알 수 없는 버전·태그는 오류로 처리합니다. 임의 값의 게임 내 의미나 게임 스크립트의 제약까지 검증하지는 않습니다.

캐릭터 추가·삭제, 변수 추가, 배열 크기 변경, 형식 변환, ERB/ERH 실행, `_Rename.csv` 치환, EM/EM+EE 고유 확장은 포함하지 않습니다. 텍스트에서 생략된 배열 끝부분은 크기를 알 수 없으므로 편집할 수 없습니다. CSV 이름표는 표준 이름 배열 중심이며 캐릭터 CSV로 게임 구조를 추론하지 않습니다.

## 정적 배포

```sh
npm run build
npm run preview
```

`dist/` 전체를 정적 호스팅의 배포 디렉터리로 지정하면 됩니다. 상대 경로로 빌드하므로 하위 경로에도 배포할 수 있으며 서버 API나 라우팅 재작성 규칙이 필요하지 않습니다. 호스팅할 때는 자산을 포함해 디렉터리 전체를 배포하세요. 실제 공개 배포나 계정 연결은 이 저장소에서 수행하지 않습니다.

사용자 파일은 Web Worker의 메모리에서만 처리합니다. 외부 폰트, CDN, 분석 SDK, 업로드 API, 쿠키, IndexedDB/localStorage 저장을 사용하지 않습니다. 앱 로드 후에는 네트워크 없이 편집·CSV 적용·다운로드가 가능합니다. 페이지 새로고침 시 작업이 사라집니다. PWA/오프라인 재접속과 `file://`에서 HTML 직접 열기는 지원하지 않습니다.

최신 데스크톱 브라우저를 대상으로 하며 Chromium에서 데스크톱 및 모바일 크기의 E2E 테스트를 수행합니다. React, TypeScript, Vite를 사용하며 파일 코어는 UI와 분리되어 있습니다.

## 검증과 개발 구조

```sh
npm test                         # 코어: 원본 보존, 인코딩, 배열, 검증, 검색
npm run build                    # TypeScript 검사 + 정적 빌드
npx playwright install chromium # 최초 브라우저 설치
npm run test:e2e                  # 실제 파일 열기/수정/다운로드/재열기
```

기준 엔진과 대조하는 테스트에는 **.NET 8 SDK**가 추가로 필요합니다. .NET은 개발 테스트 전용이며 웹앱이나 배포 산출물에는 포함되지 않습니다.

```sh
npm run fixtures        # 원본 엔진 Writer로 6종의 가상 세이브와 샘플 재생성
npm run test:reference  # 원본 엔진 Reader로 수정된 모든 값과 비수정값 대조
```

`dotnet`이 PATH에 없으면 `DOTNET=/absolute/path/to/dotnet`으로 지정할 수 있습니다. 테스트 자료는 저장소에 포함되어 있으므로 일반 개발과 `npm test`에는 .NET이 필요하지 않습니다. 기준 판독기 테스트는 전체 게임 실행 대신 저장 코드의 호환성을 검사합니다. 실제 사용자 게임 파일로 검증한 것은 아닙니다.

- `src/core/`: 형식별 파서·직렬화, 데이터 모델, 이름표, 편집·검색
- `src/worker.ts`, `src/client.ts`: 파일 처리 Worker와 타입이 있는 메시지 인터페이스
- `src/App.tsx`, `src/styles.css`: 반응형 편집 화면
- `tests/fixtures/`: 게임에서 가져오지 않은 가상 테스트 자료
- `tests/reference/`: 원본 C# 판독기/작성기 및 최소 실행 어댑터

프로덕션 라이브러리는 React(MIT), encoding-japanese(MIT), Lucide(ISC)를 사용합니다. 테스트에 포함한 Emuera 소스의 저작권과 라이선스는 [원본 라이선스](tests/reference/upstream/LICENSE.txt)와 [출처 안내](tests/reference/README.md)에 보존했습니다. 이 앱은 공식 Emuera 프로젝트가 아닙니다.
