# 🎮 Emuera Save Studio

[English](README.md) · [한국어](README.ko.md) · **日本語**

**✏️ テキスト・バイナリ編集 · 🌐 日本語 / English / 한국어 · 🔒 ファイルはブラウザー内に保持**

ブラウザーで Emuera のセーブデータを読み込み、編集できるアプリです。`global.sav` を含むテキスト形式・バイナリ形式のセーブに対応し、ファイルのアップロードやバックエンド、アカウント、別途のデータベースサーバーは不要です。アプリの画面は英語・韓国語・日本語に対応しています。

## 🚀 はじめに

ブラウザーで [Emuera Save Studio を開く](https://overworks.github.io/emuera-save-editor/?lang=ja)と、インストールせずに利用できます。**サンプルを見る**を選ぶと、自分のファイルを開く前に架空のセーブで試せます。

ローカルで実行するには Node.js 22.x（22.12 以降）、24.x、または 26.x と npm をインストールし、プロジェクトのディレクトリで次のコマンドを実行します。

```sh
npm ci
npm run dev
```

ターミナルに表示された URL をブラウザーで開きます。

新しいデスクトップブラウザーを使用してください。現在のブラウザーテストは、Chromium のデスクトップ・モバイル画面サイズを対象にしています。

アプリはヘッダーで切り替える 3 つの画面で構成されます。**スタート**（セーブまたはサンプルを開く）、**作業**（セーブを開いた後）、**ガイド**（使い方、作業の復元、オフライン、制限事項）です。ガイドを開いても、開いているセーブと編集内容は維持されます。`#guide` で直接リンクできます。

## 🌐 言語の選択

ヘッダーの言語選択で **English**、**한국어**、**日本語** を切り替えられます。最初はブラウザーが優先する対応言語を使い、対応言語がなければ英語を表示します。URL の言語指定（`?lang=en`、`?lang=ko`、`?lang=ja`）が優先されます。選択した言語は URL に反映されるため、Cookie や localStorage を使わずに再読み込み後も維持でき、ブックマークにも残せます。

言語を切り替えても、開いているセーブ、編集内容、検索条件、CSV ラベルは維持されます。ボタン、ヘルプ、エラー、通知を翻訳し、ファイル名、変数名、キャラクター名、CSV ラベル、保存値は原文のまま表示します。翻訳はアプリに含まれるため、読み込み後はオフラインでも切り替えられます。

## ✏️ セーブの編集

1. ファイル選択ボタンで `save*.sav` または `global.sav` を 1 つ開くか、セーブ専用のドロップ領域にドラッグ＆ドロップします。セーブを開いた後は、ファイル名のバーに別のセーブをドロップして切り替えられます。
2. 共通・グローバル変数、またはキャラクターを選びます。変数名、CSV ラベル、正確な配列インデックスで検索できます。多次元のインデックスは `1:2:3` と入力します。
3. 値をクリックし、新しい値を入力して変更を適用します。**変更履歴**タブで元の値と現在の値を比較できます。変更は個別にも一括でも元に戻せます。
4. **セーブをダウンロード**を選び、`original-name.edited.sav` を保存します。
5. 元のファイルをバックアップし、編集したファイルを元のファイル名に変更して、ゲームのセーブフォルダーに入れます。

アプリは別のファイルをダウンロードし、元のファイルを上書きしません。ダウンロードしたファイルは元の形式と文字コードを維持します。変更がなければ、入力ファイルとバイト単位で同一です。編集結果はダウンロード前に検証しますが、ゲームのルールや各値の意味までは確認できません。

## 📐 バイナリ配列のサイズ変更

バイナリセーブを開き、**変数グループ**で配列を選び、**配列サイズを変更**を押します。各次元の長さを入力して変更を適用してください。1～3 次元の整数・文字列配列を、次元数を維持したまま拡張・縮小でき、要素数を 0 にすることもできます。要素数の合計は 1 億以下にしてください。

既存の値は座標を維持し、新しい要素は `0` または空文字列になります。新しい範囲外の要素はダウンロードに含まれず、同じセッションで再び拡張すると、その値と編集内容が復元されます。**変更履歴**で値とサイズの変更を確認し、個別に戻すか、**すべて元に戻す**を使えます。元のサイズに戻すと追加した要素の編集は出力から除外され、有効な変更がなければ元のファイルとバイト単位で同一になります。

変更するのはセーブに保存されたサイズです。ゲーム側では別途宣言された配列サイズを使うため、追加した要素が無視される場合があります。テキストセーブには配列の完全なサイズ情報がないため、サイズ変更には対応していません。

## 🧩 バイナリ変数の追加と削除

バイナリセーブを開き、**変数を追加**を押します。名前、範囲、整数・文字列の型、単一値または配列の次元を入力してください。共通・グローバル変数は単一値と 1～3 次元に対応します。キャラクターでは組み込み変数（単一値または 1～2 次元）とスクリプトで宣言した `#DIM`・`#DIMS` 変数（1～2 次元）を選びます。新しい値は `0` または空文字列で始まり、長さ 0 の配列も使えます。同じく 1 億要素の上限が適用されます。

名前は文字またはアンダースコアで始まり、文字・結合文字・数字・アンダースコアのみを含み、UTF-16 コード単位で 128 以下にしてください。同じ範囲の有効な名前は、大文字と小文字を区別せず重複できません。これは編集機能の入力制限であり、ゲームの変数宣言を検証するものではありません。

削除するには、**変数グループ**で変数を選び、**変数を削除**を押します。**変更履歴**には追加・削除も表示され、個別に元に戻せます。元の変数を削除すると、復元するまで値とサイズの編集を非表示にします。新しく追加した変数を削除すると、追加とその編集内容を取り消します。削除した名前で新しい変数を追加した場合は、追加を取り消してから元の変数を復元してください。範囲内のすべての変数を削除しても、**すべて元に戻す**で元のバイト列を復元できます。

この機能が変更するのはセーブ内のレコードであり、ゲームの変数宣言は追加・削除しません。名前・型・範囲・次元はゲームの宣言に合わせる必要があり、存在しないレコードや不明なレコードは無視されたり、ゲームの初期値が使われたりする場合があります。[バイナリ変数の動作とソースの根拠（英語）](docs/binary-variables.md)を参照してください。

## 📝 テキスト拡張変数の追加と削除

拡張マーカーがあるテキストセーブで **変数を追加**を押すか、**変数グループ**で名前付き拡張変数を選んで **変数を削除**を押します。ゲームの宣言に合う標準・ユーザー定義の領域を選んでください。現在のセーブバージョンで使用できる型と次元のみ表示します。`MONEY`、`NAME`、`GLOBAL` など固定順序の基本変数は個別に追加・削除できません。拡張マーカーのない旧形式には変数を追加できません。

| テキスト拡張領域 | 整数 | 文字列 |
| --- | --- | --- |
| キャラクター標準変数 | 単一値・1 次元、1803 以降は 2 次元も | 単一値・1 次元 |
| 共通標準変数 | 単一値・1 次元、1708 以降は 2 次元、1729 以降は 3 次元も | 単一値・1 次元 |
| 1808 以降の共通・グローバルユーザー定義変数 | 1～3 次元 | 1 次元 |

新しい配列は指定したすべてのセルを `0` または空文字列として明示的に記録します。セーブ全体で保存値 100 万個、テキスト 100 万行、64 MiB の上限を守る必要があります。空の多次元配列はすべての長さを 0 にしてください。既存のテキスト配列は保存済みのセルと行ごとの長さを維持します。サイズ変更とテキスト形式のユーザー定義キャラクター変数の追加には対応していません。名前はバイナリと同じ入力規則に従い、元の文字コードで往復変換できる必要があります。予約されたマーカーは使用できません。

**変更履歴**、個別の取り消し、**すべて元に戻す**、キャラクターの複製、任意のローカル復元にも反映します。元の変数を削除すると編集内容を非表示で保持し、新しい変数の追加を取り消すと、その編集内容も削除します。変更していないレコード・区切り・BOM・文字コード・既存の改行を維持し、新しいレコードにはその領域の改行を使います。すべての変更を取り消すと元のバイト列を正確に復元します。セーブへのレコード追加はゲーム変数の宣言や初期化にはなりません。[テキスト変数の動作とソースの根拠（英語）](docs/text-variables.md)を参照してください。

## 👥 キャラクターの複製と削除

通常のテキスト・バイナリセーブでキャラクターを選び、**キャラクターを複製**を押します。編集内容を含む現在の値・配列サイズ・変数構成を独立したコピーとして末尾に追加します。`NAME` と `NO` もコピーされるため、必要なら複製後に編集してください。`NO` は画面上の保存順（`#0`、`#1`、…）とは別で、重複も可能です。空のキャラクターも複製できますが、コピー元がなければ新規キャラクターは作れません。ゲームスクリプトや CSV からの初期化は行いません。

**キャラクターを削除**の確認画面で、影響を受ける標準参照を確認できます。後続のキャラクターは 1 つ前に移ります。整数セル `TARGET:0`・`ASSI:0`・`MASTER:0`・`PLAYER:0` は同じキャラクターを参照するよう調整し、削除対象への参照は `-1` にします。負の値と既に範囲外の値は維持します。ゲーム独自の参照、他の配列要素、`NO`、`RELATION` のインデックスは調整しません。ゲームが別の場所に保存する参照は手動で確認してください。

**変更履歴**にはキャラクターの操作と自動参照調整も表示します。元のキャラクターの削除を取り消すと値・変数の編集内容・元の順序が復元され、手動で編集していない参照も戻ります。標準参照を手動編集すると、入力時にその位置にいたキャラクターを引き続き参照します。自動調整を上書きするには参照値を編集し、調整を取り消すにはキャラクターの操作を取り消してください。コピーの削除はその複製と編集を取り消します。すべてのキャラクターを削除しても、**すべて元に戻す**で元のバイト列を復元できます。グローバルセーブでは、この機能を提供しません。

テキストでは、固定順の基本ブロックとキャラクターの拡張ブロックを一緒に複製・削除します。元の文字コード・BOM・区切り・改行を維持します。新しい境界で単独の CR と LF が結合する場合のみ、LF を 1 つ挿入して 2 行を維持します。保存されている参照セルのみ調整し、省略されたセルは追加しません。複製したテキスト配列も行ごとの長さと編集可能なセルを維持します。

ソースの根拠、参照規則と検証範囲は [バイナリキャラクターの動作（英語）](docs/binary-characters.md)と [テキストキャラクターの動作（英語）](docs/text-characters.md)を参照してください。

## 🎮 ゲームプリセット

エディターの **ゲームプリセット** を選ぶと、翻訳された項目名・説明と、よく使う項目へのショートカットを表示します。一覧には **eraTWKR Textbung（TWKR 1.20 ベース）**、**eratohoK 1.29.3**、**eraMegaten KR Rev.143**、**ShinEraTenseiP 0.5.9** を含みます。参照した版と変数定義へのリンクも表示します。ゲームコードとバージョンから候補を案内し、同じコードを使うゲームをバージョンで区別できない場合は手動で選びます。コードやバージョンの違いを表示しますが、識別情報の一致はすべてのパッチやエンジン改変版との互換性を保証しません。

**よく使う項目** を開いてキャラクターを選ぶと、そのキャラクターのショートカットが有効になります。共通の所持金を含むプリセットでは直接開けます。ショートカットは保存済みの項目を開きます。現在の画面言語のプリセット名・説明でも、選択した範囲と変数グループ内で検索できます。存在しない項目や型の異なる項目は利用できません。CSV ラベルを優先し、プリセットの案内は別に表示します。

プリセットを選択・変更してもセーブの値や編集内容は維持します。言語の切り替えやファイルを開く処理の失敗では選択を維持し、別のセーブを正常に開くと初期化します。ローカル作業の復元が有効な場合、選択したプリセットも復元します。アプリの読み込み後はオフラインでも利用できます。一部の項目を案内する機能であり、ゲームデータ全体や値の自動変更を提供するものではありません。[プリセット対応表・参照した版・検証範囲（英語）](docs/game-presets.md)を参照してください。

## 🏷️ CSV ラベルと文字コード

セーブを開いた後、**ゲーム CSV ラベル**の領域に、ゲームの `ABL.csv`、`TALENT.csv`、`EXP.csv`、`PALAM.csv`、`ITEM.csv`、`FLAG.csv`、`CFLAG.csv` など、対応する標準ラベルファイルをドロップします。複数の CSV をまとめてドロップするか、**CSV を読み込む**ボタンで選択できます。点線で示されたセーブと CSV の領域は、それぞれ対応するファイルを受け付けます。それ以外の場所にドロップしてもファイルは開きません。ラベルは値を名前で探すための任意の機能で、セーブ内容や配列サイズを変更しません。ラベルが競合した場合は、先に読み込んだ名前を維持して警告を表示します。

`Chara*.csv` を読み込むと、参照用の名前・呼び名・あだ名・主人の呼び方を表示します。ファイルの `NO` または `番号` をセーブ内の現在の `NO` と対応付け、ファイル名やキャラクターの位置は使いません。キャラクターを選んで **キャラクター CSV** を開くと情報を確認できます。セーブ内の名前の項目と `NO` の横にもラベルを表示し、`RELATION` のインデックスには該当するキャラクター番号の名前を付けます。ラベルで検索でき、`RELATION` は呼び名やあだ名でも検索できます。`NO` を編集すると対応先も変わります。セーブ内の名前は変えず、初期能力値やキャラクターの追加は適用しません。キャラクター番号が重複した場合は最初のファイルの情報を維持します。

`_Rename.csv` はエンジンの `置換する内容,別名` 形式による検索用の置換に対応します。例えば `ABL:0,focus` を読み込むと `[[focus]]` で、`0,skill` を読み込むと `ABL:[[skill]]` で検索できます。置換後の検索語は検索欄の下に表示します。選択した範囲内で変数名・ラベル・数値インデックス、または `TA:3:2:1` のような参照を検索します。別名は大文字と小文字を区別し、読み込んだルールの順に一度ずつ置換します。重複した定義は最初の内容を維持します。置換の対象は検索入力だけです。CSV の名前やセーブの値は変えず、式や `TARGET` のような動的なキャラクター指定は評価しません。

CSV の読み込みは 1 セッションで合計 64 MiB までです。別のセーブを正常に開くと初期化し、ローカル作業の復元が有効な場合は作業とともに CSV 情報も復元します。対応する項目、カンマのエスケープ、上限については [CSV の構文とソースの根拠（英語）](docs/csv-metadata.md)を参照してください。

テキストの文字コードは、まず UTF-8 として検証し、無効な場合は CP932/Shift-JIS を使用します。両方の文字コードで有効なバイト列もあります。文字が正しく表示されない場合は、**読み込み文字コード**で適切な文字コードを選び、**選択した文字コードで再読み込み**を押してください。再読み込みでは、確認後に編集内容を破棄します。文字コードの選択は、その後に読み込む CSV にも適用されます。

## ✅ 対応範囲

基準は、コミット [`85db4cbd`](https://github.com/0x00000FF/Emuera/tree/85db4cbd5eb2efe6c5b5449ada351a21a20db60b) に保存された標準 **Emuera 1.824** です。

| 項目 | 対応範囲 |
| --- | --- |
| セーブの種類 | 通常の進行セーブとグローバルセーブ |
| テキストセーブ | 基本・拡張セクション、BOM の有無を問わない UTF-8、CP932/Shift-JIS |
| バイナリセーブ | 形式バージョン 1808 |
| 値 | 符号付き 64 ビット整数、文字列、最大 3 次元の配列 |
| 編集 | 既存の値、省略されたバイナリ配列の 0・空文字列、次元数を維持するバイナリ配列のサイズ変更、バイナリ・テキスト拡張変数の追加・削除、通常テキスト・バイナリキャラクターの複製・削除 |
| サイズ制限 | 1 ファイル 64 MiB、バイナリ配列ごとに 1 億要素、保存された値 100 万個、テキスト 100 万行 |

「CSV セーブ」と呼ばれることもあるテキストセーブは Emuera 独自の形式で、ラベル用の CSV ファイルとは異なります。1700、1708、1729、1803、1808 のテキスト拡張マーカーを認識します。一般的な値の検証には基準エンジンが生成する 1808 形式を使い、キャラクター操作では基本形式と認識するすべての拡張マーカーを架空の基準データで検証します。

既存キャラクターを複製せずに新規作成すること、固定順序のテキスト基本変数の追加・削除、テキスト配列のサイズ変更、形式変換、ERB/ERH の実行、EM/EM+EE 固有の拡張には対応していません。テキスト配列の末尾で省略された要素は、宣言されたサイズが分からないため編集できません。テキスト形式の多次元文字列配列は、基準エンジン自体が対応していません。キャラクター CSV の情報と検索用の置換は、ゲーム構造やスクリプトを推定・実行しません。

範囲外の整数、元の文字コードで表現できない文字、予約されたテキスト区切り文字、テキスト値の改行、破損したファイルや未対応のファイルはエラーになります。自動互換性検証には、元のエンジンの保存コードで生成・読み込みした架空のセーブを使っています。ユーザーからは実際のセーブデータの読み込み・編集・出力も確認されています。この報告はゲームでの再読み込み、すべてのゲーム・派生版の互換性、配列サイズ変更・変数追加と削除・キャラクター複製と削除の実セーブでの検証までは示しません。

## 🗺️ 今後の対応予定

未対応の機能を順次実装しています。バイナリ配列のサイズ変更、バイナリ・テキスト拡張変数の追加・削除、通常テキスト・バイナリキャラクターの複製・削除、キャラクター CSV の名前情報、`_Rename.csv` による検索用の置換、任意のローカル作業の復元、オフライン再アクセス・PWA のインストールは実装済みで、残る項目は次のとおりです。

- 複製せずに新規キャラクターを作成すること。
- 必要なサイズ情報を明示して行うテキスト配列のサイズ変更と形式変換。
- 専用の形式資料とテストデータを用いた EM/EM+EE 形式への対応。
- `file://` での実行。
- 別途実行設計が必要な ERB/ERH の実行。

実装と検証が完了するまで、各項目は未対応です。提供時期は未定です。

## 💾 ローカル作業の復元

**このブラウザーに作業を保存**は初期状態では無効です。有効にすると、1 作業分をブラウザーに自動保存し、再読み込みや同じサイトへの再アクセス時に復元します。元のファイル、適用済みの値・構造の編集、取り消しの状態、読み込んだ CSV、読み込み文字コード、ゲームプリセット、検索語、選択した範囲・変数とページを保存します。開いている編集画面で未適用の入力は保存しません。別のセーブを正常に開くと保存内容を置き換え、読み込みに失敗した場合は維持します。

ページを離れる前に**ブラウザーに保存済み**を確認してください。復元機能を無効にすると、確認後に保存済みの作業を削除し、現在の作業はメモリーに残します。保存エラーが発生しても、現在の編集内容と最後に保存できた作業は維持します。**保存を再試行**するか、編集済みファイルをダウンロードしてください。別のタブが保存内容を変更・削除した場合、古い状態のタブでは自動保存を停止します。

現在のブラウザープロファイルとサイトのパスごとの IndexedDB を使用し、ブラウザー・端末間の同期は行いません。復元の記録は操作 10 万回、元のファイル・CSV を含めて 128 MiB までです。上限に達した場合、編集済みファイルをダウンロードして開き直し、新しい作業を始めてください。ブラウザーのデータ削除、保存領域の整理、プライベートウィンドウの終了で保存内容が失われることがあるため、ダウンロードしたバックアップも保管してください。オフライン用のアプリの準備と作業の復元は別の機能です。オフラインで開き直したときに作業も復元するには、復元を有効にしてください。

## 📴 オフライン利用とインストール

接続中に本番用アプリへアクセスし、スタート・作業画面の下部にある復元設定の横に**オフラインで再アクセス可能**と表示されるまで待ってください。その後は、このブラウザーで接続なしにアプリを開き直し、サンプルと全 3 言語を利用できます。初回のアクセスには接続が必要です。オフライン再アクセスには HTTPS または localhost と、サービスワーカー・アプリの保存領域を許可するブラウザーが必要です。開発サーバーではオフライン利用の準備を行いません。ブラウザーのデータ削除や保存領域の整理でアプリのキャッシュが失われることがあります。**オフライン利用・インストール**を開くと、準備の再試行や更新の確認ができます。

開き直したときに編集作業も続けるには、**このブラウザーに作業を保存**を有効にして、**ブラウザーに保存済み**を確認してください。無効の場合は、閉じる前に編集済みファイルをダウンロードしてください。アプリをインストールしても復元は自動で有効になりません。復元を無効にすると保存済みの作業は削除しますが、アプリのキャッシュは維持します。

対応環境では**アプリをインストール**またはブラウザーのインストールメニューを使ってください。iPhone・iPad では**共有 → ホーム画面に追加**を使います。インストールは任意で、対応状況はブラウザーによって異なります。通常のブラウザータブでも利用できます。インストール済みアプリの起動時はブラウザーが優先する対応言語を使い、言語別のブックマークは URL の `lang` 値を保持します。

**新しいバージョンの準備ができました**と表示されたら、編集画面の未適用の入力を先に適用し、各ウィンドウの作業を保存またはダウンロードしてください。このアプリのすべてのタブとインストール済みアプリのウィンドウを閉じ、開き直すと新しいバージョンが適用されます。更新によって編集画面を自動で再読み込みすることはありません。このアプリの他のウィンドウが開いている場合、1 つのタブを再読み込みしても以前のバージョンを使い続けることがあります。更新の準備に失敗した場合は、以前のオフライン版を維持します。`file://` での直接実行は引き続き未対応です。

## 🔒 プライバシーと作業データ

セーブと CSV の内容は初期状態ではブラウザーのメモリー内に保持し、ローカル作業の復元を有効にすると、このブラウザーの IndexedDB にも保存します。オフライン利用の準備では、架空のサンプルを含む配布用アプリのファイルだけをブラウザーの Cache Storage に自動で保存します。読み込んだセーブと CSV はこのキャッシュに入れません。アップロード API、アクセス解析、外部フォント、CDN への依存はありません。Cookie と localStorage は使用せず、言語設定は URL にのみ保持します。

アプリの読み込み後は、ネットワーク接続なしで編集、CSV の読み込み、ダウンロードと有効にしたローカル保存ができます。アプリの準備が完了すると、オフラインでの再アクセスも可能です。アプリをインストールしていても、ローカル作業の復元が無効の場合はページの再読み込みや終了で作業が失われます。
