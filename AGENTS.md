# Agent context

This is the repository-wide entry point for coding agents, maintained in English. Read [CONTRIBUTING.md](CONTRIBUTING.md) for setup, validation commands, contribution guidelines, and documentation policy. The [README](README.md) is the user guide.

## Product scope

Emuera Save Studio is a static browser application with English, Korean, and Japanese interfaces. It edits values in normal and global saves from standard Emuera, using text or binary formats, resizes binary arrays without changing their rank, adds/deletes binary variable records, and duplicates/deletes characters in normal text and binary saves. Files stay in browser memory unless the user enables local session recovery in IndexedDB. The baseline is Emuera 1.824 at commit `85db4cbd5eb2efe6c5b5449ada351a21a20db60b`; see [reference provenance](tests/reference/README.md).

Current scope excludes character creation without copying, individual text variable addition/deletion, text array resizing, format conversion, ERB/ERH execution, and fork-specific EM/EM+EE formats. `_Rename.csv` is supported for search substitution; character CSVs provide optional name metadata. Local session recovery is optional and off by default. There is no backend, account system, PWA, or `file://` entry point. Planned support is tracked in the README.

## Implementation invariants

1. Store save integers as `bigint`. Use decimal strings for input, display, and UI-facing results; never convert save values through JavaScript `number`.
2. Treat the parsed document and its original bytes as immutable. Separate overlays store value edits, binary dimensions, variable additions/deletions, character copies/deletions, and reference bindings. Resizing keeps coordinates, type, and rank. Out-of-bounds values and edits stay in memory for restoration but are excluded from export, queries, and active change counts. Deleting an original variable/character retains its hidden edits; deleting an added variable or copied character cancels it and its edits. `Editor.reset()` restores the original state. Original variable IDs are positions in `document.variables`; additions and copied variables use monotonically increasing IDs that are never reused within an editor. `scope === -1` means shared/global; otherwise scope is a stable character ID (original position, or a new monotonically increasing copy ID), never `NO`. `CharacterSummary.index` is the current export position, or null for a deleted character. Never use IDs directly as export positions. Scalar keys are `''`; array keys are comma-separated coordinates such as `'1,2,3'`.
3. Keep arrays sparse. Missing binary cells mean `0n` or `''` within current bounds; added variables start at those defaults. Query pages contain at most 50 rows, including variable and character structure rows in the changes view; pagination, resizing, copying, and export validation must not expand an entire sparse array.
4. Export by patching edited text value spans or changed binary records. Preserve untouched bytes, headers other than an intentionally changed character count, relative order of original variables, section markers, BOM, and line endings. Insert added binary records at the recorded section boundaries. Binary character copies go before the shared section; text copies go before shared base records and before shared extension records separately. At a new text boundary where a bare CR would merge with an LF, insert one LF to retain two line endings; never split an existing CRLF in a patch. Omit deleted records or entire deleted character spans. No-op and fully reverted exports must be byte-identical to the input.
5. Reparse the exact export and verify intended variable membership, order, scope, character section, type, dimensions, and all logical values within those bounds before returning it. Check values with stable editor IDs, not export positions. Keep integer, encoding, bounds, malformed-file, and resource-limit checks. Reject unsupported versions/tags rather than guessing a layout.
6. Text cells are editable only when they have entries in `textSpans`. Do not invent trailing array sizes or fill gaps in ragged text arrays. Reject reserved text delimiters, line breaks, NUL, and characters that cannot round-trip through the original encoding.
7. A Worker `open` request replaces the current editor only after the new save parses successfully. Failed opens must preserve the existing session. Keep the heavy processing in the Worker. Tie query results to the save revision and current filters; stale rows must stay read-only throughout debounce and Worker processing, including their undo actions.
8. CSV names are optional display metadata. They must not change save structure or values; conflicts retain the first loaded name and produce warnings. Character CSVs match the current signed 64-bit `NO`, never the filename or character position. Preserve saved names in `scopeName`; expose CSV metadata separately. `RELATION` indices use character NO. `_Rename.csv` substitutes search input only, in import order with a single literal pass per rule. Never evaluate expressions or substitute CSV contents or saved values. See [CSV semantics](docs/csv-metadata.md).
9. Keep the editor and Worker locale-independent. `MessageError` carries a plain `Message` descriptor; translate it in the UI at render time. `VariableRow.scopeName` and character summary names contain only save data and may be empty; shared/global and unnamed-character labels are UI fallbacks. A language change must not reopen a save, reset edits, translate user content, or alter serialization. Language preference is stored only in the URL (`lang`), with browser detection and English fallback.
10. Character copies snapshot current exported values, sizes and membership, including NAME/NO, independently of later source changes. Shared integer 1D cells `TARGET:0`, `ASSI:0`, `MASTER:0`, and `PLAYER:0` bind valid positions to stable character IDs. Export/display remaps those IDs; a deleted target gives `-1`. Manual edits bind against current positions. Text reference bindings apply only to cells present in `textSpans`; omitted cells are never added. Negative/out-of-range literals, other cells, NO, RELATION and custom references stay unchanged. Automatic reference rows are undone through the character operation, not a misleading value undo. See [binary character semantics](docs/binary-characters.md) and [text character semantics](docs/text-characters.md).
11. Game presets are optional display and navigation metadata backed by pinned game source editions. Do not infer compatibility from game code/version alone, apply edits through selection, or overwrite CSV labels. Resolve shortcuts with stable scope/variable IDs and current bounds. The UI translates field guides and supplies matching coordinates for search; the Worker stays locale-independent and restricts matches to editable cells. Clear the preset only after a successful save open. See [preset evidence and limits](docs/game-presets.md).
12. Local recovery is off by default. Persist original bytes plus a versioned, validated operation journal, CSV imports and view settings only when enabled. Replay through the editor API to preserve hidden edits, undo, copy independence, stable IDs and selected text encoding. Keep recovery work in the Worker and serialize requests across asynchronous storage. Commit metadata and operations atomically; report saved only after transaction completion. Storage failures must preserve live edits and the last committed recovery. Compare stored tokens to reject stale-tab writes, including after deletion. Disabling recovery clears its stored data and must not allow queued writes to restore it. Never persist language preference or unapplied dialog input.

Resource limits currently include 64 MiB per file, 100 million cells per binary array, 1 million stored values, 1 million text lines, 200,000 variables, and 100,000 characters. Keep these limits effective when changing parsing or iteration.

Recovery additionally bounds its journal at 100,000 operations and 128 MiB including the original file and CSV imports. Exceeding recovery limits stops saving, not in-memory editing or download.

## Format pitfalls

- Binary files begin with `89 45 52 41 0D 0A 1A 0A`. Version 1808 uses little-endian numbers and **UTF-16LE** strings with .NET 7-bit encoded **byte-length** prefixes. Do not replace this with UTF-8 or a character count. Only normal/global file types are supported.
- Character binary records before `0xfd` are built-ins, and those after it are user-defined variables; `0xfe` ends the character and `0xff` ends the file. Preserve existing separators, including empty sections. Add one separator when adding user-defined variables to an unseparated character. New shared/global variables allow ranks 0–3, character built-ins 0–2, and user-defined character variables 1–2. Save records do not declare game variables; see [binary variable semantics](docs/binary-variables.md).
- Text saves use engine syntax, not generic CSV parsing. Preserve the fixed legacy variable order and literal `__FINISHED`, `__EMU_SEPARATOR__`, and `__EMUERA_*_STRAT__` markers. `STRAT` is the engine's spelling. The 1700 marker is `__EMUERA_STRAT__`; later recognized markers are 1708, 1729, 1803, and 1808.
- Text character base blocks precede shared base records; character extension blocks follow the version marker and precede shared extensions. Keep these spans separate, including empty extension sections. Order variables by `textSection`, then stable character order, then byte position. Relocate every copied `textSpans` entry and retain the selected encoding when snapshotting. Enforce the line limit even without a final newline.
- Text multidimensional string arrays are unsupported by the reference engine. Binary arrays and ragged numeric text arrays have different shape/editability rules.
- Automatic text detection tries strict UTF-8 before CP932/Shift-JIS. A manual override is needed for ambiguous byte sequences. CSV imports use the selected encoding too; never silently substitute unrepresentable characters during export.
- Standard CSV comments are whole lines starting with `;`; `;!;` activates the remainder of a line. A semicolon inside a label is literal. `_Rename.csv` has separate syntax: `replacement,token`, escaped commas (`\,`) in replacements, and comments only at column zero (including `;!;`). Standard filename families and aliases live in `labels.ts`. Lookups for format markers, CSV families, and character fields must exclude inherited object properties.

## Validation and handoff

Use the change-specific checks in [CONTRIBUTING.md](CONTRIBUTING.md). Build before browser tests: Playwright serves `dist/`, including the Worker and demo asset. Parser/serializer/encoding work also needs the .NET reference comparison when the SDK is available; report it explicitly if unavailable.

The committed fixtures are synthetic. The reference test compares the original C# reader's full value dictionaries before and after edits, so do not replace it with a check that only uses our own codec. Keep `tests/reference/upstream/` sources and their license unchanged; adapters are separate. These checks exercise save-code compatibility, not a running game or every fork.

Maintain `AGENTS.md` and `CONTRIBUTING.md` in English. Keep README files and their `.ko.md` / `.ja.md` translations synchronized. Documentation-only changes need link and content checks, not application test reruns. In the handoff, describe observable changes, checks performed, and any remaining compatibility or verification limits.
